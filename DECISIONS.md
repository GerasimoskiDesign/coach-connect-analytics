# Decisions log

Decisions made while building this repo unattended. Each entry: what, why.

## Source and copy

1. **Source path.** No path was given. A search of the user folders and `C:\` for `angular.json` inside a folder whose name contains "coach" found exactly one match: `C:\Coach_Connect_V2\coach-connect-client`. Used that.
2. **Copied only git-tracked files** of the frontend (`git ls-files coach-connect-client`). That excludes `node_modules`, `dist`, `.angular` cache and anything untracked. No git history, no backend (`CoachConnect/`), no ML service (`ml-service/`), no thesis files.
3. **Source CLAUDE.md protocol not applied here.** The source repo's CLAUDE.md asks for approval pauses before every step. This task is a separate, unattended repo built from a read-only copy, and the instruction for this run is explicit about working without stopping, so the pause protocol was not used. The source repo was never modified.
4. **Build fix: component style budget.** The unchanged source failed `ng build` (production) because four components exceed the `anyComponentStyle` budget (largest is 26.4 kB vs an 8 kB error limit). Smallest fix: raised that budget to 32 kB warning / 40 kB error in `angular.json`. No packages were upgraded.

## Mock backend

5. **One HTTP interceptor** (`core/mock/mock-backend.interceptor.ts`) answers every `/api/v1/*` call from an in-memory database seeded with a fixed random seed, so data is identical on every load and in CI. Users and booked sessions are kept in `localStorage` so a reload keeps you logged in.
6. **New sign-ups are created as already onboarded.** The original product sends new users through a 5 to 6 step onboarding form. For a demo whose purpose is the measurement layer, the mock gives new users a default synthetic player profile so they land on the dashboard. The onboarding and profile edit screens still work against the mock.
7. **Prices are EUR.** Display labels changed from MKD to EUR. Wire field names such as `estimatedPriceMkd` were kept so the DTO contract matches the real backend; in this demo the value is EUR.
8. **ML service disabled.** `mlServiceUrl` is empty in both environments, so the fire-and-forget call to the Python service never happens. Recommendations come from the mock and are ranked by the A/B variant.

## Measurement layer

9. **GTM ID in two places, kept in sync by a test.** The IDs live in `environment.ts` / `environment.prod.ts` as asked, but the GTM snippet has to be static HTML in `index.html` so it runs before Angular boots. `tests/unit/container.test.mjs` fails if the IDs in the environments, `index.html` and `gtm/container.json` ever differ.
10. **Stored consent is re-applied in `index.html`, not in the Angular component.** The inline script reads `cc_consent` and calls `gtag('consent','update', ...)` right after the default and before GTM loads. Doing it from Angular would race GTM's Initialization tags, which only wait 500 ms (`wait_for_update`). The banner component reads the same key to decide whether to show itself and pushes the update when the visitor clicks.
11. **Consent banner sits in the page flow, above the app.** A first version floated at the bottom of the screen and covered the sign-up button (the Playwright suite caught it). In the flow it never blocks a form.
12. **`page_title` comes from the route, not `document.title`.** Angular's router emits `NavigationEnd` before it updates `document.title` (checked in `@angular/router` source), so reading the document would report the previous page's title. Routes now carry a `title`, and the service reads it from the activated route snapshot.
13. **Automatic page_view is off in the Google tag** (`send_page_view: false` through a Configuration Settings variable). All page views come from `page_view_spa`, mapped to `page_view` by a lookup table. Otherwise the first page of every visit would be counted twice.
14. **Two GA4 event tags instead of one.** GTM keeps the last `ecommerce` object in its data model. With "Send ecommerce data" on a single tag that fires for every event, `book_session`, `search` and `page_view` would carry the items of the previous ecommerce event. One tag sends ecommerce data for the four ecommerce events; the other sends plain parameters for the rest. Both use the same event-name lookup and measurement ID.
15. **Event-scoped keys are reset on every push.** Same data model persistence problem for plain keys: a `value` from `book_session` would otherwise attach to every later event through the shared parameter table. `AnalyticsService.push()` sets the event-scoped keys an event does not use to `undefined`. A Playwright test replays the dataLayer the way GTM merges it and fails if any event would carry a stale parameter.
16. **User properties.** `set_user_properties` is pushed whenever the set of user properties changes: first app start in a browser session, sign-up, login, a player level resolved after login. The last set sent is stored in sessionStorage (`cc_user_props_sent`); on later page loads with the same set it is pushed as plain keys (no event) so the Data Layer Variables still resolve. Logout clears the account keys with a plain push. It is attached to every GA4 hit through a shared Event Settings variable and on each event tag, since the Google tag fires on Initialization, which can run before Angular has pushed the variant.
17. **`index` is the 1-based rank shown in the UI.** GA4 accepts any integer; using the visible rank makes "CTR by position" read naturally (position 1 is the top card).
18. **Dashboard shows 5 recommendations instead of 3**, so position analysis has more than three slots. `view_item_list` reports exactly the items shown.
19. **`search` fires on explicit submit only** (Enter or the Search button), carrying the current level and city filters. Changing a filter alone does not count as a search. A text search box was added to the coaches page; the mock filters on name, city, level and specialty.
20. **Demo checkout page** (`/checkout/:requestId`). The original product has no payments. After a paid booking request, the player lands on a checkout summary with a "Pay N EUR" button. No card fields exist. Paying confirms the session in the mock and fires `purchase`. The item in `purchase` is the booked session: price is the amount paid, quantity 1, so revenue equals the sum of price x quantity. `purchase` is deduplicated per transaction ID in sessionStorage.
21. **`book_session` values.** `session_type` is `coaching` whenever a coach is on either side, including a coach's request to a player (then `coach_id` is the coach's own ID), and `practice` only for a free player-to-player session (then `coach_id` is `none` and `value` is 0). `value` is the price the mock stored for the request, after any loyalty discount.
22. **`set_user_properties` is sent to GA4 as an event** (it has its own trigger, `CE - set_user_properties`). It carries the user properties and is harmless as an event; it can be excluded in reports.

## Tests and tooling

23. **Google endpoints are stubbed in Playwright.** `googletagmanager.com` answers with an empty script and GA endpoints are blocked, so CI never sends test traffic to the real GA4 property. The test still asserts the GTM request for `GTM-M69PG8QQ` is made.
24. **Tests run against the GitHub Pages build**, served locally under `/coach-connect-analytics/` with the same `404.html` fallback (`scripts/serve-dist.mjs`).
25. **`npm test` now runs the unit and Playwright suites.** The original `ng test` (Karma) had no spec files.
26. **`tests/e2e/package.json` sets `"type": "module"`** so the specs can import the same ESM tracking-plan reader as the GTM generator.
27. **Playwright pinned to 1.49.1**, a release well over two weeks old.
28. **Each event tag sends exactly the top-level parameters its events have in the tracking plan**, plus `user_id`. The generator derives the tables from `docs/tracking_plan.csv`, so `rec_algorithm` and `player_level` are on both tags (`book_session` is a plain event, `select_item` and `purchase` are ecommerce events). The unit test rebuilds the expected tables from the plan.
29. **Content-based scores include a small continuous rating term.** Without it the best matches all scored exactly 1.0, so `rec_score` carried no information and ties were broken by id.
30. **Dev proxy removed.** `proxy.conf.json` forwarded `/api` to a local .NET backend that is not part of this repo; the mock answers every call before the network.
31. **Docs written by a subagent, then checked.** The four docs in `docs/` (except the tracking plan) were drafted in parallel by a subagent from the code, the container and this log. Its review found a stale comment, a missing `item_list_name` in the tracking plan and an unused parameter mapping; all three are fixed.

## Publishing

32. **Not published.** `gh` is not installed on this machine. The only other way to create the repo unattended was to read the stored GitHub credential from Git Credential Manager and call the GitHub API; the permission system denied that, and working around it would not be appropriate. ## Phase 1 for the GA4 interview demo (2026-11-11)

33. **Account keys nested under `user` in the dataLayer** (`user.user_id`, `user.user_role`, `user.signup_date`, `user.player_level`). `user_role` and `player_level` also exist as event parameters with a different meaning (the player in that session versus the signed-in account). Top-level keys would clash, and the per-push reset of event-scoped keys would wipe the user properties. GTM merges nested objects key by key and `undefined` clears a key, so logout pushes all four as `undefined`.
34. **Parameter allow-list in `AnalyticsService.push()`.** Only keys from the tracking plan (top level, `user`, `ecommerce`, items) reach the dataLayer; anything else is dropped with a console warning in dev builds. Values that look like an email address are replaced with `(redacted)` anywhere, and phone numbers in `search_term`. A unit test fails if `EVENT_SCOPED_KEYS` drifts from the plan.
35. **Item names are IDs, not people.** `item_name` was the coach's full name; it is now `Coach <first 8 characters of the ID>` (players: `Player <id8>`), so no person's name reaches GA4. Item reports therefore show IDs.
36. **Player level bands** 1-4 `amateur`, 5-7 `intermediate`, 8-10 `professional`, as specified. The user property comes from the player profile, fetched once after login when the level is not known yet. The demo's register form has no skill field, so a new player gets the mock's default level 5 (`intermediate`) until the profile is edited.
37. **Player recommendations report `rec_algorithm` = `skill_match`.** The mock ranks recommended players by skill and city for everyone, whatever the A/B arm. Labelling them with the coach variant would mix them into the A/B test, so A/B analysis filters on `rec_coaches`.
38. **Mock fix: price of a coach's request.** The mock priced a request only from the receiver's hourly rate, so a coach's request to a player stored no price and the event reported `value` 0 and `practice`. The price now comes from whichever side is the coach, for new requests and reschedules.
39. **Mock fix: the Players toggle returned coaches.** `/recommendations/me` read `type` from `HttpParams`, but the service puts `?type=players` in the URL string, so the player list was always coaches. The mock now reads the full URL.
40. **`sign_up` with `method` = `auto_login`.** The mock creates an account when someone logs in with an unknown email. That account is new, so the login screen now fires `sign_up` (`auto_login`) instead of `login`. The mock flags it with `accountCreated: true` in its login response; the real backend has no such field and never auto-creates accounts.
41. **One exact-match Custom Event trigger per event** instead of two regex triggers. Every event can be seen and paused on its own in GTM, and a regex can no longer catch an event by accident. A unit test checks there is exactly one trigger per plan event, on the right tag.
42. **`optional_parameters` column in the tracking plan.** `book_session` always carries `rec_list_id`, `rec_algorithm` and `rec_index`, but they only have a value when the booked person was clicked in a recommendation (otherwise an empty string, never a stale earlier click). Purchase items carry the same context. Optional parameters are allowed by the tests, but required ones are always checked.
43. **Recommendation context kept in sessionStorage.** The click is stored per clicked person at `select_item` (`cc_rec_clicks`), moved to the request at `book_session` (`cc_rec_bookings`) and read at `purchase`, so it survives route changes and reloads. sessionStorage is per tab, so a booking finished in another tab has no recommendation context.
44. **`session_request_responded`** fires on accept, decline and reschedule (`response` = `rescheduled`) on the Requests page, with `responder_role` from the signed-in user. A single-user journey never receives a request from another user, so the simulation does not produce this event; the Playwright tests cover it by placing a pending request in their own browser's mock storage.
45. **`user_id` on the Google tag and on every event.** It is set in the Configuration Settings, for a page that loads signed in, and in the shared Event Settings so it follows login and logout inside the single-page app. Known limit: after logout in the same page load, gtag may keep the configured `user_id` for later hits until the page reloads. It is the account's UUID, never an email.
46. **Traffic simulation in `simulation/`, separate from the tests.** It does not use the Playwright helper that stubs Google requests. Consent is set with `context.addInitScript` before the first load, and the run stops if consent, the update order or GTM are wrong. `BASE_URL` accepts only the live demo URL or `http://localhost` / `127.0.0.1`; localhost is for the local test, run with `--block-ga` so nothing reaches GA4.
47. **The simulation waits before closing a page.** gtag batches hits, and closing a page right after an event lost hits in early runs (`search`, `book_session`). Each visit now ends with a 5 to 7 second dwell and a close with `beforeunload`. Every journey compares its dataLayer events with the GA4 requests it saw (`missingInGa` in the log).
48. **Nothing deployed, nothing committed, GTM and GA4 untouched**, as instructed for Phase 1.
