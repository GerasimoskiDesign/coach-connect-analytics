# GTM manual setup

How to build the container in [`gtm/container.json`](../gtm/container.json) by hand in the Google Tag Manager UI. Use this if **Admin > Import Container** fails or is not available. Importing is faster and is described in [section 5](#5-import-instead-of-building-by-hand).

| Setting | Value |
|---|---|
| GTM container | `GTM-M69PG8QQ` (web) |
| GA4 measurement ID | `G-GQKEFPELG9` |
| Source of truth | `gtm/container.json`, generated by `node gtm/build-container.mjs` from `docs/tracking_plan.csv` |

Names below match the container file exactly. Keep them identical: the docs, the generator and the tests all use these names.

What gets built: 1 built-in variable, 34 user-defined variables, 11 triggers, 3 tags.

## 1. Built-in variables

1. **Variables** > **Built-In Variables** > **Configure**.
2. Make sure **Event** (under Utilities) is checked. It is on by default in new containers.

The lookup table in step 2.3 reads `{{Event}}`.

## 5. Import instead of building by hand

1. In GTM, open container `GTM-M69PG8QQ` > **Admin** > **Import Container**.
2. **Choose container file** > select `gtm/container.json` from this repo.
3. **Choose workspace**: **New**, and give it a name (for example `Import tracking plan`). Using a new workspace keeps the import separate from anything else in progress. **Existing** also works.
4. **Choose an import option**:
   - **Merge** keeps what is already in the workspace and adds the imported items. Then pick **Rename conflicting tags, triggers, and variables** (safe: nothing is lost, duplicates get a new name) or **Overwrite conflicting tags, triggers, and variables** (imported items replace items with the same name).
   - **Overwrite** replaces the whole workspace with the file. Only use it on an empty or disposable workspace.
5. Review the summary of new, modified and deleted items. Into an empty container: 3 tags, 11 triggers and 34 variables added. Into a container that has the previous version (GTM-M69PG8QQ today): 11 triggers and 16 variables added, the 3 tags and some existing variables modified. Click **Confirm**.

**Updating a container that already has the previous version** (as GTM-M69PG8QQ does): choose **Merge** > **Overwrite conflicting tags, triggers, and variables**. Do not use Rename for this update: the tag names are the same in both versions, so Rename keeps the old tags next to the new ones and every event reaches GA4 twice. After the import, delete the two old triggers `CE - GA4 events` and `CE - GA4 ecommerce events` (no tag uses them any more). The Tags list should then show exactly 3 tags.

After a Merge, check the Tags list for a second Google tag for `G-GQKEFPELG9` (for example one created when the container was set up). Two Google tags for the same ID send duplicate configuration; keep only `Google tag - GA4`. If anything was renamed during a Rename merge, check that the names in sections 2 to 4 still match exactly.

## 6. Verify with Preview

1. Click **Preview**, enter `https://gerasimoskidesign.github.io/coach-connect-analytics/` and click **Connect**.
2. In Tag Assistant, check:
   - `Google tag - GA4` fires on the Initialization event of each page load.
   - **Consent** tab: all four signals `denied` by default, then `granted` after accepting the banner.
   - Each tracking plan event fires exactly one GA4 event tag: the ecommerce tag for `view_item_list`, `select_item`, `view_item`, `purchase`; the custom and recommended tag for the rest.
   - **Variables** tab on an event: the DLV values are filled for that event and `undefined` for event-scoped keys it does not use (page keys and `rec_variant` always keep a value).
   - **Data Layer** tab: every ecommerce event is preceded by `{ ecommerce: null }`.
3. In GA4 DebugView, check the parameters per event. The full per-event checklist is in [GA4 setup, section 7](GA4_SETUP.md#7-testing-gtm-preview-and-ga4-debugview).
4. When everything checks out: **Submit** > **Publish and Create Version**, add a **Version name** and **Version description**, and click **Publish**.

## 7. Consent

The site runs Consent Mode v2: `src/index.html` sets all four consent signals to `denied` before GTM loads and re-applies a stored choice (`localStorage` key `cc_consent`). The banner sends the update.

Google tags (the Google tag and GA4 Event tags) have built-in consent checks. They read `analytics_storage` and the ad signals themselves and adjust what they send, so no extra consent triggers, blocking triggers or additional consent requirements are needed. That is why every tag's Consent Settings stay at **Not set**.

To review this in the UI: **Admin** > **Container Settings** > check **Enable consent overview** > **Save**. The Tags list then shows a consent overview icon (a shield) that lists each tag with its built-in consent checks.
